# D-16 — Blender support is a v2 candidate; v1 stays Godot-only

**Status:** ANSWERED by the human, 2026-08-11.

**Decision:** Blender joins the future list as a v2 candidate. No v1 wave allocates
work to it. Godot 4.7.x remains the only v1 engine.

**Notes for v2 planning:**
- The `Driver` protocol (operator/src/openxr_operator/driver.py) is the intended seam;
  a Blender driver must fit it without contract changes. If it cannot, that is a
  contract amendment through swarm/requests/, not a local workaround.
- Blender's Python API likely simplifies scene-tree observation and property access
  relative to Godot; the OpenXR API-layer capture work (W6, gated on D-04) is
  Godot/OpenXR-specific and does not transfer. Blender VR viewport observation design
  is deferred to v2 research.
- The five frozen contracts, the approval gate, the audit log, and the D-14
  plain-language surface apply unchanged to any future Blender driver.

**Rationale:** protects v1 delivery for the Godot audience while keeping the
architecture honest about multi-engine intent.
