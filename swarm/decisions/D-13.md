# D-13 — Backend fallback behaviour

**Status:** ANSWERED by the human, 2026-08-09 (as part of option B).
Supersedes kit v2.1's D-12 (same topic, same answer).

**Decision:** Manual configuration only — no automatic fallback. If the
configured backend is unreachable, the run fails with a clear error naming
the backend and the port. It does not silently switch to another backend,
hosted or otherwise. Automatic fallback would mean a screenshot of the
project leaving the machine at a moment nobody chose, which is exactly the
property this project exists to avoid.

**Enforcement:** `backends.resolve()` raises `ModelUnreachable` with the
backend named; there is no fallback code path to delete.
