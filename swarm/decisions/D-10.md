# D-10 — Model backend policy

**Status:** ANSWERED (human delegated to agent, 2026-08-09); AMENDED same day
after audit of kit v2.1 (V-ledger). Kit D-09 is the Godot 4.8 policy; this
register continues from it. Supersedes kit v2.1's D-09 (same topic).

**Decision:** ModelBackend(Protocol) with per-provider adapters, resolved
fail-closed through `backends.resolve()`. Twelve adapters registered
(`backends/__init__.py`): four local, eight hosted. Shipped today:
`local_ollama` (reference) and `local_llamacpp`. Registered-but-unshipped
adapters resolve to a named error, never a silent fallback; hosted adapter
implementation is gated on per-provider endpoint verification (kit v2.1 §4.4).

**Harvested from kit v2.1:** the registry/resolution design, FORBIDDEN_HOSTS
permanent denylist, Meta-lineage model denylist at startup, env-var-only
credentials, per-adapter capability declaration.

**Fixed on the way in (v2.1 audit):** the permanent denial is applied
centrally in `resolve()`, not per-adapter `__init__` (V-09); local adapters
pointed off-loopback are rejected at startup; constrained-decoding mode is
declared per adapter and carried on every response (V-13); registration is
by explicit import, not unstated side-effect (V-17).

**Consequences:**
- Egress allowlist is configuration; the denylist is not (see D-11).
- Anything below "native" constraint degrades to validate-and-retry and
  the run report must record it.
- New backend adoption remains a human stop point.
