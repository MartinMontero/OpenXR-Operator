# D-10 — Model backend policy

**Status:** ANSWERED (human delegated to agent, 2026-08-09). Kit D-09 is the
Godot 4.8 policy; this register continues from it.
**Decision:** Protocol + multiple adapters. `ModelBackend(Protocol)` in
`operator/src/openxr_operator/model.py` mirrors `Driver(Protocol)` on the
engine side. Ollama is the reference backend; llama.cpp/llama-server and
generic OpenAI-compatible adapters are registered, not yet shipped.

**Defect resolved:** kit v2.0 shipped a concrete `OllamaClient` with no seam
(§2.2 diagram plane, §6.2 class, §3.6 hardcoded egress port, §2.7 step 8,
§4.4, M5) while the engine side got a swappable Driver protocol. Same
problem, opposite treatment, no justification.

**Consequences:**
- Egress allowlist is configuration, not a literal port in prose.
- Every adapter declares its constrained-decoding mode; anything below
  "native" degrades §3.5's posture to validate-and-retry and the run
  report must record it.
- New backend adoption remains a human stop point.
