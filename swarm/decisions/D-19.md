# D-19 — Multi-engine roadmap and device/privacy scope

**Status:** ANSWERED by the human, 2026-11-01.

**Requirement (human's words, paraphrased):** OpenXR Operator must support
Godot, Blender, Unity, and Unreal Engine, and users must be able to use what
they build on any XR device. The Meta/OpenAI/xAI ban is a dev-side privacy
boundary, not a restriction on target hardware.

**Decision:** Accepted as the product roadmap, with explicit sequencing —
this is not a v1 commitment to four engines at once.

1. **Godot first (v1).** Prove the full loop with a real non-developer.
2. **Blender next (D-16).** Its Python API makes observation/actuation
   comparatively straightforward.
3. **Unity and Unreal after that.** Each gets its own driver behind the
   frozen `Driver` protocol. No contract changes are permitted to weaken
   gates: token-first auth, capability allowlist, plain-language approval
   (D-14), hash-chained audit log, fail-closed resolution. If an engine
   cannot meet a gate, that engine does not ship — the gate does not bend.

**Device scope (clarification):** what users build with the agent are
ordinary Godot/Blender/Unity/Unreal projects. Device support is inherited
from those engines and from OpenXR runtimes — PC headsets via SteamVR or
Monado, standalone headsets via their OpenXR support, Quest hardware via
OpenXR on Quest. OpenXR Operator itself adds no runtime dependency of its
own and no server of any kind.

**Privacy scope (clarification):** the vendor ban is dev-side. The tool
never contacts Meta/OpenAI/xAI endpoints and never uses their SDKs or
models. Spatial data (frames, scene trees) stays on the user's machine by
default (D-12); a hosted model is opt-in only and would carry the §3.6
disclosure. Building FOR Quest hardware or using OpenXR runtimes is not a
gate violation — Meta's cloud and Meta's data collection are what is
excluded, not Meta's hardware.

**Non-goal of this decision:** simultaneous multi-engine support in v1,
and any promise of app-store publishing (Quest Store, Steam) — that is the
user's own engine/deployment concern.
