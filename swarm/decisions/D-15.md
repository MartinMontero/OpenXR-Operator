# D-15 — Kimi (Moonshot AI) as an optional hosted model backend

**Status:** ANSWERED by the human, 2026-08-11 (question surfaced by external audit discussion).

**Decision:** A `hosted_moonshot` adapter (Kimi K3.1 Pro class, vision-capable) is
approved for a **future wave**, strictly opt-in. It is not v1 default scope.

**Constraints (unchanged gates):**
- D-12 stands: local first, not local only. Local Qwen2.5-VL-7B remains the default.
- D-13 stands: no automatic fallback. Hosted Kimi is only ever reached by explicit
  manual configuration, never by failover.
- Vendor gate: Moonshot AI is not Meta/OpenAI/xAI — provider passes. The configured
  model must still pass `assert_model_allowed`.
- Egress: exactly one allowlisted provider domain, verified against current provider
  documentation at implementation time (adapter-verification gate, `backends/VERIFIED.md`).
- §3.6 trade-off disclosure is mandatory in onboarding text: with this adapter enabled,
  project screenshots and scene trees leave the machine.
- Open-weight Kimi models are not viable on the measured hardware floor (S-11: 16 GiB
  RAM class); this decision covers the hosted API only.

**Rationale:** strong vision+code capability as an opt-in for users who accept the
hosted trade-off; zero impact on users who never configure it.
